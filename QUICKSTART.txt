Midterm 视频分析系统 - 快速启动
更新时间：2026-07-20

1. 启动基础服务

    bash scripts/midterm_start.sh

   首次启动会检查 GPU/Docker、准备数据目录和模型、构建镜像，并预创建但不启动
   8090 管理的双分支容器。

2. 打开操作台

    http://127.0.0.1:8090/operator

   浏览器只连接 8090。内部 API 的 8000 端口不应直接暴露。

3. 登记摄像头和算法

   - 进入“配置 -> 摄像头”；
   - 填写名称、RTSP 地址、ROI 和算法规则；
   - 批量双分支运行时，登记阶段可以不选择“加入当前运行”。

4. 选择并启动完整链路

   - 点击首屏“选择摄像头并启动”；
   - 生产 T4 选择 40 路，系统分成 20/20，分析 4 FPS；
   - 本机 4090 选择 60 路，系统分成 30/30，分析 8 FPS；
   - 也可以手动指定 A/B；
   - 点击“启动完整双分支”。

   页面会显示：启动前预检 -> 双分支/TensorRT -> 摄像头收敛 ->
   rolling-cache 预热 -> 开放 evidence。任务在 API 后台执行，刷新页面后可继续查看
   状态；API 进程重启会中断该任务。

5. 验收

   在“启动与运行”检查：

   - A/B source 数量正确；
   - 每路最近帧持续更新；
   - forwarder queue 和 send failure 不增长；
   - 端到端延迟没有持续升高；
   - evidence task 能收敛；
   - 视频约 24 FPS、5+5 秒，bbox/timeline 可见；
   - 人员轨迹页能显示命中图片。

6. 注册人脸（可选）

   在“人员与人脸”选择单张或多张清晰照片，填写唯一人员编号和姓名。完整双分支
   预设使用 ROI AdaFace worker；4090 预设不使用 CUDA MPS，但仍启用该人脸链路。

7. 停止

   - 只停止完整采集/推理：在 8090 点击“停止完整链路”；
   - 停止整套服务：bash scripts/midterm_stop.sh

   8090 停止操作会让部分 worker 继续收尾，不等同于整栈停止。

常用检查

    bash scripts/midterm_health.sh
    bash scripts/runtime/doctor_midterm.sh

注意：midterm_health.sh 的固定服务清单仍偏向旧单分支；双分支、rolling-cache 和
person-observation-worker 应同时从 8090 运行总览判断。
