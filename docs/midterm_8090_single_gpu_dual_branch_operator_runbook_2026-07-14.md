# 8090 单卡双分支启动流程说明（操作员视角）

更新说明：2026-07-20 已按当前工作区复核。文件名保留首次成文日期。

## 1. 这份说明解决什么问题

本文说明操作员如何从 8090 实际页面进入“单张 GPU、双 Savant 分支”运行模式，
并按生产 T4 40 路基线核对参数、执行应用、判断完整 evidence 链是否就绪或恢复
单分支。

本版本新增了两个受控运行预设：

- `生产 T4 40 路完整链路`：20+20、4 FPS、YOLO batch 4、AdaFace batch 16、
  MPS 45%/45%/10%、ROI AdaFace、rolling-cache、5+5 证据链。
- `本机 4090 60 路完整链路`：30+30、8 FPS、YOLO batch 4、AdaFace batch 16、
  不启用 MPS，但仍启用 ROI AdaFace、rolling-cache 和 5+5 证据链。

首次部署或代码更新后，管理员先执行 `scripts/midterm_start.sh`。该脚本会预创建
这些容器但保持停止；之后双分支完整链路由 8090 页面负责启动和切换。压测清理不
应删除这些 operator-managed 容器。

访问地址：

```text
http://192.168.1.100:8090/operator
```

页面主路径：

```text
8090 操作台
  -> “配置 -> 摄像头”添加摄像头并配置算法
  -> 点击首屏深绿色“系统启动入口”中的“选择摄像头并启动”
     （也可点击摄像头页“选择并启动完整链路”，或进入“启动与运行”）
  -> “完整链路快速启动”
       -> 选择生产 T4 40 路或本机 4090 60 路
       -> 从已登记摄像头中勾选本次参与运行的路数
       -> 系统自动均分，或手动指定 A/B
       -> “启动完整双分支”
  -> 页面验收完整 evidence 链、source、queue 和轨迹
```

“高级运维”中的性能和拓扑表单保留用于诊断与自定义配置，不再作为普通操作员的
推荐启动入口。

## 2. 先说明当前版本的真实边界

8090 当前确实有“推理拓扑”页面和“双分支同卡”选项，不需要操作员手写
topology JSON。选择完整运行预设后，页面动作还会管理：

- dynamic source adapter；
- `analysis-forwarder-a/b`；
- `savant-a/b`；
- `replay-a/b`；
- `video-file-sink-a/b`；
- source 到 A/B 的分配和 runtime epoch。

完整运行预设还会启动和配置：

- CUDA MPS daemon 及 T4 的 45%/45%/10% 配额；
- `adaface-roi-worker`；
- `replay-raw-fanout-a/b` 直连双 Savant，并同时发布分析采样和原始码流；
- `rolling-cache-sink-a/b`；
- event-worker/media-worker 的 rolling、5+5、WIP 和 remux 参数。

页面会等待双分支 source 收敛、ROI worker、rolling sink 和证据链容器就绪后才返回
成功。页面显示“双分支正在运行”与“完整 evidence 链已就绪”是两个不同状态。

启动采用后台任务：操作员点击后可以刷新 8090，任务不会因页面刷新而丢失。页面
进度条依次显示预检、A/B TensorRT 初始化、摄像头收敛、rolling-cache 预热和
evidence 开放；生产 T4 预设的 rolling-cache 固定预热时间为 25 秒，并显示倒计时。
如果 B 分支独立模型缓存缺少 ONNX，预检会直接阻止启动，不再进入容器重启循环。

### 2.1 生产现场结论的时效性

本文最初记录的 2026-07-14“日常单分支、enabled camera=0、预检不通过”只是当时
快照，已经失效，不能作为当前页面状态。2026-07-15 的后续审计记录生产 T4 已运行
`production_t4_40`：40 路启用、A/B 20/20、完整 evidence 链就绪，并连续运行约
4 小时。

每次操作仍必须以当前页面的 profile、所选摄像头、topology plan、pipeline ready 和
apply-status 为准。`/runtime/control` 的兼容 mode 字段可能仍显示 single，不能单独用它
否定实际双分支；应联合看 A/B 容器、source 数、topology plan 和完整链 ready 状态。

后续生产审计见：
`docs/code_review/production_runtime_evidence_audit_2026-07-15.md`。

## 3. 谁负责哪一步

| 角色 | 负责内容 |
| --- | --- |
| 操作员 | 摄像头状态、8090 性能/拓扑参数、确认应用、页面验收、恢复单分支 |
| 系统管理员 | 首次部署 A/B 容器及 raw fanout、CUDA MPS、ROI worker、rolling sink、生产挂载和镜像 |
| 压测/研发人员 | 40 路正式门禁、温度/功耗、FPS、queue、evidence、bbox、轨迹验收 |

如果“结构预检”显示容器缺失，操作员应停止在该页面，不应尝试通过反复点击、强制
重启或临时关闭 evidence guard 绕过。管理员需要先完成双分支生产依赖预置。

## 4. 启动前必须满足的条件

开始前逐项确认：

1. 计划投入运行的生产摄像头已经在 8090“摄像头”页面登记。
2. 目标是 40 路时，在“完整链路快速启动”中选择 40 路已登记摄像头；顶部“启用”
   数量可以仍为 0，启动确认时系统会一次性批量启用所选摄像头。
3. 这些应是真实生产摄像头，不要重新启用历史 `压力摄像头 xx` 作为日常源。
4. 当前没有正在生成的关键 evidence；“运行状态 -> 证据生成”不应持续显示
   `pending`、`materializing`、`finalizing`。
5. “运行总览”没有 source 未收敛、容器反复重启或明显健康告警。
6. 管理员已经预置双分支核心容器和它们的依赖；“结构预检”最终必须全部满足。
7. T4 当前散热条件下只使用 40 路基线，不选择 60 路。

这份流程只要求摄像头已经登记、RTSP 地址和算法配置有效，不要求提前逐路启用。
快速入口会先检查所选摄像头和双分支容量，预检通过后在同一个受控操作中批量更新
启用状态并应用拓扑；未点击启动时不会改变任何摄像头运行状态，也不会逐路触发
当前单分支同步。

## 5. 第一步：进入运行状态页

1. 浏览器打开 `http://192.168.1.100:8090/operator`。
2. 点击顶部一级入口 **“运行”**。
3. 点击二级入口 **“运行状态”**。
4. 在“运行总览”右上角点击 **“刷新状态”**。
5. 先阅读“建议下一步”和下面三项差异：
   - 实际链路；
   - 视频源收敛；
   - 目标拓扑。

正常准备状态应满足：

- 页面数据可以完整加载；
- 没有“部分状态未加载”；
- 已登记摄像头数量和快速入口所选数量符合预期；
- “证据生成”没有阻塞任务；
- 如果实际仍为单分支，可以继续准备拓扑切换。

如果页面优先显示 **“恢复视频源”**，先处理视频源收敛问题，不要直接切拓扑。

## 6. 第二步：核对推理性能

1. 在“运行总览”点击 **“高级运维”**。
2. 找到 **“推理性能”** 面板。
3. 先核对保存值与运行值。生产 T4 40 路基线建议如下：

| 页面字段 | 40 路基线 |
| --- | ---: |
| Forwarder 采样 | 开启 |
| 采样最大 FPS | `4/1` |
| 采样最小 FPS | `99/25` |
| 转发队列上限 | 2048 |
| Savant 入流限速 | 开启 |
| Savant 最大 FPS | `4/1` |
| Savant 最小 FPS | `99/25` |
| Savant 并行流上限 | 64 |
| Savant batch | 4 |
| 姿态 batch | 4 |
| 人脸检测 batch | 4 |
| AdaFace batch | 16 |
| 姿态 interval | 1 |
| 人脸 interval | 3 |
| AdaFace interval | 3 |
| 批量推送等待 | 10000 us |

“推理性能”中的值主要对应基础单分支运行配置。双分支启动时，FPS、batch、并行流
和 push timeout 还必须在下一步的 A/B 分支参数中分别填写；不能只改这一处。

- **“保存草稿”**：只保存，不重启。
- **“确认并应用”**：会重建当前 forwarder/Savant，并触发 evidence guard。

如果只是准备双分支，建议先保存草稿，再在“推理拓扑”中填写 A/B 参数；不要为了
改一个数字连续重启单分支和双分支两次。

## 7. 第三步：填写单卡双分支拓扑

继续在“高级运维”区域找到 **“推理拓扑”**。

### 7.1 核心选择（高级运维备用入口）

普通操作员不需要填写本节参数。进入“完整链路快速启动”并选择命名预设后，系统
会锁定已验证的参数；本节只用于高级诊断、审计和自定义拓扑。

| 页面字段 | 应填写 |
| --- | --- |
| 目标拓扑模式 | **双分支同卡** |
| 分片策略 | **按数量均分** |
| 每分支目标路数 | **20** |

不要选择“自动”。明确使用“双分支同卡”可以避免 enabled camera 数量变化后自动在
单/双分支之间切换，也避免误选不存在的 GPU1。

### 7.2 分支 A

| 页面字段 | 应填写 |
| --- | ---: |
| GPU | 0 |
| batch | 4 |
| 姿态 batch | 4 |
| 人脸 batch | 4 |
| AdaFace batch | 16 |
| 并行流上限 | 64 |
| Forwarder FPS | `4/1` |
| Forwarder 最小 FPS | `99/25` |
| Savant FPS | `4/1` |
| Savant 最小 FPS | `99/25` |
| 批量推送等待 | 10000 us |

### 7.3 分支 B

分支 B 填写与分支 A 完全相同，GPU 也必须是 **0**。

### 7.4 计划分配

在面板底部检查拓扑计划：

- 启用摄像头：40；
- 分支 A 计划路数：20；
- 分支 B 计划路数：20；
- A/B GPU：都为 0；
- 每路摄像头只出现在一个分支中。

如果现场希望固定某些摄像头到指定分支，可以把“分片策略”改成“手动覆盖”，页面
会显示每路摄像头的 A/B 下拉框。普通 40 路生产运行优先使用“按数量均分”，减少
人工漏配和两支不均衡。

## 8. 第四步：检查结构预检

“推理拓扑”面板会显示 **“结构预检”** 和预检明细表。以下项目必须全部显示
“满足”：

- A/B Savant 容器存在；
- A/B analysis-forwarder 容器存在；
- A/B Replay 容器存在；
- A/B video-file-sink 容器存在；
- 每支计划路数不超过并行流上限。

页面可能无法在 API 容器内执行 `nvidia-smi`，所以“GPU known”可能是非致命提示；
但 A/B GPU 字段必须明确为 0，管理员也必须已经验证 Docker 能访问 T4。

### 8.1 看到“不满足”怎么办

- 容器显示 `missing`：停止操作，联系管理员预置双分支 profile。
- 计划路数超过并行流上限：提高上限或减少摄像头，不能强行应用。
- enabled camera 不是 40：返回“摄像头”页核对，不要用错误路数启动。
- evidence guard 提示仍有任务：等待任务完成后刷新，不要绕过。

“结构预检”只证明容器和容量前提，不代表双分支已经运行，也不证明 ROI、rolling
evidence 已启动。

## 9. 第五步：保存并应用

预检全部满足后：

1. 可以先点击 **“保存草稿”**，刷新页面确认值没有丢失。
2. 点击 **“确认并应用”**。
3. 浏览器弹出确认框：

   ```text
   确认保存并应用目标拓扑？这会切换 source、analysis-forwarder 和 Savant；
   证据生成中时服务端会阻止操作。
   ```

4. 确认后等待页面完成，不要重复点击，也不要在应用过程中关机。
5. 服务端会依次：
   - 检查 active evidence；
   - 停止现有 source adapter；
   - 停止基础单分支 forwarder/Savant；
   - 创建新的 runtime epoch；
   - 写入 A/B module/source/replay shard 配置；
   - 重建并启动 A/B Savant 和 forwarder；
   - 启动 A/B Replay 和 video-file-sink；
   - 按 A/B 计划重新创建 source adapter。

页面成功提示应类似：

```text
拓扑已应用：双分支同卡，容器动作 xx 个，source 40 路
```

启动 TensorRT engine 可能需要数分钟。页面动作最长允许等待约 15 分钟；期间不要
把“暂时还没 ready”误判成失败，也不要同时点击“受控重启运行时”。

## 10. 第六步：从 8090 判断是否真正启动成功

应用完成后回到“运行总览”，点击 **“刷新状态”**，按以下顺序验收。

### 10.1 建议下一步 / 配置差异

- 实际链路：**双分支正在运行**；
- 目标拓扑：**双分支同卡**；
- 不显示目标与实际漂移；
- 视频源已收敛；
- 不再显示“应用已保存拓扑”。

### 10.2 推理拓扑表

- A/B GPU 都为 0；
- A/B 计划路数为 20/20；
- A/B 推理路数最终为 20/20；
- 推理容器和限流容器均为运行/healthy；
- queue 保持 0；
- 累计发送失败不增长。

### 10.3 摄像头性能

- 40 路都有“最近有帧”；
- 最近帧时间持续更新；
- 有效 FPS 稳定在约 4 FPS；
- 模型输出计数持续增加。

### 10.4 分析限流

- 40 路都能看到收到帧和转发帧；
- queue 不持续增长；
- 累计发送失败为 0 或不增长；
- 原始约 24 FPS 到分析 4 FPS 的采样丢弃是预期，不等于视频 evidence 只有 4 FPS。

### 10.5 证据生成

- 新事件能从 pending/materializing 收敛到 materialized；
- 不出现持续增长的 expired/failed；
- 切换前已有 evidence 仍可在“告警证据”页面播放。

### 10.6 用户可见结果

产生真实事件后继续检查：

1. “证据 -> 告警证据”：MOV 可播放、约 24 FPS、5+5 秒、bbox 可见。
2. “证据 -> 人员轨迹”：按人员 ID/编号可查到轨迹图片。
3. 如果双分支正常但没有 ROI 人脸轨迹或 rolling 视频，应判断为完整生产依赖没有
   启动，不能把“推理拓扑已运行”当作全链成功。

## 11. 常见失败及用户该怎么做

| 页面现象 | 含义 | 用户动作 |
| --- | --- | --- |
| 结构预检：容器 missing | A/B 容器未预置 | 停止，联系管理员；不要反复应用 |
| 启用摄像头为 0 | 没有生产源参与计划 | 返回摄像头页核对 |
| A/B 不是 20/20 | 分片或 enabled camera 不正确 | 不应用，修正后刷新 |
| evidence guard 阻止 | 有证据正在生成 | 等待收敛，不强制 |
| 实际单分支、目标双分支 | 保存了草稿但没应用，或应用失败 | 看预检与错误详情后再处理 |
| 双分支仅部分运行 | A/B 某个容器未 ready/退出 | 不继续启源，联系管理员查容器 |
| source 未收敛 | 动态源没有按计划启动 | 点击建议区“恢复视频源”；仍失败则停止 |
| queue 持续增长 | 推理吞吐不足或链路异常 | 停止扩容，不降低验收门槛 |
| 有视频但无轨迹 | ROI worker/人脸链不完整 | 联系管理员检查 ROI AdaFace |
| 有推理但无 rolling 视频 | rolling sink/evidence 链未启动 | 联系管理员检查 rolling-cache |

## 12. 如何恢复为日常单分支

优先使用拓扑切换，不要只停止一半容器：

1. “运行 -> 运行状态 -> 高级运维 -> 推理拓扑”。
2. 目标拓扑模式选择 **“单分支”**。
3. 点击 **“确认并应用”** 并确认提示。
4. 等待基础单分支重启和 source 收敛。
5. 刷新状态，确认：
   - 实际链路为单分支；
   - 双路扩展停止；
   - 基础单路链路运行；
   - 视频源重新收敛。

“更多运行操作”中的 **“停止双路扩展”** 只会停止 A/B 扩展，不会自动恢复完整
单分支。它适合应急止损，不是正常回退流程。如果已经应急停止双路，应继续点击
“启动基础单路链路”，再按建议区提示执行“恢复视频源”。

## 13. 当前已补齐的一键化能力与剩余边界

当前已经纳入 topology apply 的内容：

1. 首次部署时预创建缺失的 A/B、raw fanout、rolling、ROI 和 MPS 容器；
2. CUDA MPS 生命周期和 45%/45%/10% 配额；
3. ROI AdaFace worker 的启动、健康等待和 batch=16；
4. raw fanout 直连 Savant，同时保留原始约 24 FPS rolling 输入；
5. rolling-cache sink A/B、24 FPS、5+5 证据路径和 SSD 缓存挂载；
6. media-worker/event-worker 的完整生产参数；
7. rolling prefill 后再开放 evidence task，避免启动头部产生短视频；
8. 页面区分“推理双分支已运行”和“完整 evidence 链已就绪”。

仍未在本阶段纳入的是运行中的 RTSP 断流故障注入、双分支自动回滚和 worker restart
soak。这些必须在 8090 完整启动链路先通过一次 40 路启动 smoke 后再执行。

## 14. 操作员最终检查单

只有以下项目全部满足，才可以向现场确认“单卡双分支已正常启动”：

- [ ] 目标拓扑为“双分支同卡”
- [ ] 实际链路为“双分支正在运行”
- [ ] enabled camera 为 40
- [ ] A/B 都绑定 GPU0
- [ ] A/B 计划与推理 source 为 20/20
- [ ] 双 YOLO batch 为 4，AdaFace batch 为 16
- [ ] 分析 FPS 约为 4 FPS
- [ ] forwarder queue 不增长，send failure 不增长
- [ ] 40 路最近帧持续更新
- [ ] evidence task 能收敛到 materialized
- [ ] 新 MOV 可播放、5+5 秒、约 24 FPS、bbox 可见
- [ ] 人员轨迹可以查询并显示图片
- [ ] ROI worker、rolling sink 和 MPS 已由管理员确认运行
- [ ] T4 温度和功耗没有进入持续降频状态
