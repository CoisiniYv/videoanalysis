# R3.2B Raw Clip Evidence MVP

Status: implementation MVP. R3.2B extends R3.2A metadata and snapshot evidence
with controlled `raw_clip.mp4` handling.

R3.2B does not generate `annotated_clip.mp4`. Annotated clip remains
optional/on-demand only for debug or report export after the performance
baseline.

R3.2B must not create default dual video output. One event must not
automatically produce both `raw_clip.mp4` and `annotated_clip.mp4`.

R3.2B does not change the Savant pipeline and does not run performance tests.

## Scope

`raw_clip.mp4` is the canonical production evidence video when a reliable
Replay/NVR/raw segment source exists. It should be generated by remux/copy when
possible and should not reencode by default.

The shared event flow is:

```text
event
  -> evidence_task
  -> metadata.json
  -> snapshot.jpg
  -> raw_clip.mp4 when a reliable clip source exists
  -> events.clip_path / payload.media.raw_clip_path / media_status
  -> evidence_tasks.clip_path / status
  -> GET /api/v1/events/{event_id}/evidence
```

If metadata and snapshot are ready but the clip source is unavailable, the
event remains queryable with:

```text
media_status=partial
clip_status=not_implemented
raw_clip_path=null
clip_error_message=...
```

Clip failure must not block event insertion, metadata, snapshot, or the
evidence API.

## Clip Source Strategy

Priority 1 is a reliable ReplayClient or replay source:

```text
frame_uuid
keyframe_uuid
replay request id
source_id + event_ts_ms mapped to replay segment
raw mp4 fallback path
```

ReplayClient currently exists for keyframe lookup and replay job creation, but
this worker does not yet have a production file materialization contract from
Replay/NVR into the event evidence directory. Until that contract exists,
production raw clip generation returns `clip_status=not_implemented`.

Priority 2 is explicit `raw_mp4_fallback`. This is smoke/debug only and must be
enabled by passing an absolute source MP4 path. It writes:

```text
/data/video-analytics/media/events/YYYY/MM/DD/<event_id>/raw_clip.mp4
```

with:

```text
clip_capture_mode=raw_mp4_fallback
exact_event_clip=false
fallback_used=true
fallback_reason=explicit_debug_raw_mp4_fallback
remux_or_copy=true
reencoded=false
```

R3.2B does not use live RTSP current clip recording as a production default.
It must not record the current live stream for ten seconds and pretend that it
is the event pre/post clip. Any future live current fallback must be explicitly
debug-only and must write `clip_capture_mode=rtsp_current_debug`,
`exact_event_clip=false`, `fallback_used=true`, and `fallback_reason`.

## Metadata Schema Additions

`metadata.json` includes:

```json
{
  "evidence": {
    "raw_clip_path": ".../raw_clip.mp4",
    "annotated_clip_path": null,
    "clip_status": "ready",
    "clip_error_message": null
  },
  "clip": {
    "clip_capture_mode": "raw_mp4_fallback",
    "pre_seconds": 5,
    "post_seconds": 10,
    "exact_event_clip": false,
    "remux_or_copy": true,
    "reencoded": false,
    "fallback_used": true,
    "fallback_reason": "explicit_debug_raw_mp4_fallback"
  }
}
```

When no reliable clip source exists:

```json
{
  "evidence": {
    "raw_clip_path": null,
    "annotated_clip_path": null,
    "clip_status": "not_implemented",
    "clip_error_message": "no reliable replay/raw clip source available"
  },
  "clip": {
    "clip_capture_mode": "not_available",
    "exact_event_clip": false,
    "remux_or_copy": true,
    "reencoded": false,
    "fallback_used": false,
    "fallback_reason": null
  }
}
```

## API

`GET /api/v1/events/{event_id}/evidence` returns 200 for ready, partial, failed,
and not_implemented media states. The response includes:

```text
media_status
clip_status
clip_path
clip_url
raw_clip_path
raw_clip_url
annotated_clip_path
annotated_clip_url
clip_error_message
metadata_path
snapshot_path
evidence_tasks
```

`clip_path` points to `raw_clip.mp4` when generated. It must not point to an
annotated video by default.

## Media Policy

R3.2B follows R3.1C retention policy. It does not use `video-file-sink` or
`metadata-sink` debug output as production evidence and does not perform
continuous full recording.

Production deployments should keep media worker concurrency bounded and
snapshot-first / clip-later behavior. If storage or clip source limits are hit,
events remain in the database, metadata and snapshot are preserved where
possible, and clip generation degrades to `not_implemented`, `failed`, or
future `storage_limited`.
