# Phase 3E — Annotated Snapshot MVP

Date: 2026-05-25

## Design Goal

Generate an annotated evidence snapshot from the raw Phase 3C snapshot using Pillow (PIL). Draw event bbox, text label block, and zone/ROI polygon (if available) on the raw JPEG. Store annotation metadata in `payload.media`, expose `annotated_snapshot_url` from FastAPI.

## Annotation Content

Each annotated snapshot includes:

1. **Bbox rectangle** — red outline drawn from `payload.bbox {x, y, width, height}`
2. **Text label block** — opaque dark block in top-left corner with:
   - Event ID (truncated to 8 chars)
   - Event type and camera ID
   - Track ID and confidence percentage
   - UTC timestamp
3. **Zone polygon** (conditional) — green outline if polygon coordinates are in payload (`payload.polygon` or `payload.zone_polygon`)

## Zone Overlay Policy

- Polygon present (>=3 points): draw green outline, `zone_overlay_status = "ok"`
- Only `zone_id` present (no polygon coords): skip, `zone_overlay_status = "skipped_missing_polygon"`
- No zone data at all: no zone_overlay_status set
- Polygon with <3 points: silently skipped

## Annotation Output

- Target directory: `/media/snapshots/annotated/{event_id}.jpg`
- Source: raw snapshot at `events.snapshot_path` (generated by Phase 3C)
- Idempotent: if annotated file already exists on disk, status promoted to `ready` without re-generation
- Does NOT overwrite raw snapshot
- Does NOT modify `clip_status` or `snapshot_status` on annotation failure

## Fields Stored (all in `payload.media`)

| Field | Type | Description |
|---|---|---|
| `annotated_snapshot_status` | string | `"ready"` or `"failed"` |
| `annotated_snapshot_path` | string | Absolute path to annotated JPEG |
| `annotated_snapshot_error_message` | string | Present only on failure |
| `zone_overlay_status` | string | `"ok"` or `"skipped_missing_polygon"` or absent |

Note: `annotated_snapshot_path` is stored in the JSONB payload (not a top-level column), so no DB migration is required.

## API Exposure

```json
{
  "annotated_snapshot_path": "/media/snapshots/annotated/{event_id}.jpg",
  "annotated_snapshot_url": "/media/snapshots/annotated/{event_id}.jpg",
  "media": {
    "annotated_snapshot_status": "ready",
    "annotated_snapshot_path": "/media/snapshots/annotated/{event_id}.jpg",
    "zone_overlay_status": "skipped_missing_polygon"
  }
}
```

Both `GET /api/v1/events/recent` and `GET /api/v1/events/{event_id}` return these fields.

## Media Worker Loop Order

```
run_worker() loop:
  1. _process_sink_output()       — detect clips from sink (Phase 3B)
  2. _process_pending_snapshots() — raw snapshot generation (Phase 3C)
  3. _process_pending_annotations() — annotated snapshot (Phase 3E)
```

Annotation runs after raw snapshot because it reads from `snapshot_path` + `snapshot_status=ready`.

## Savant Pipeline

NOT touched. No draw_func, no nvosd, no encoder, no GPU pipeline changes. The annotation is pure post-processing in the media-worker.

## Known Limitations

1. **No annotated clip / video overlay** — annotation is on a single JPEG frame only. Annotated video clips are deferred.
2. **Bbox may not align perfectly** if the snapshot frame differs from the detection frame (timestamp-domain mismatch inherited from Phase 3C technical debt #1).
3. **Font fallback** — uses DejaVuSans if available, else PIL default bitmap font. DejaVuSans is available in `python:3.12-slim-bookworm` base image.
4. **Zone polygon must be in event payload** — currently Savant phase2c events only include `zone_id`, not polygon coordinates. Zone overlay will show `skipped_missing_polygon` until the event export probe is updated to include polygon data.
