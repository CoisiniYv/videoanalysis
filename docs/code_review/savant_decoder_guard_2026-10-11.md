# Savant 解码输出重复身份保护

日期：2026-10-11，Asia/Seoul（KST，UTC+09:00）。

在 `7ea424f` 的 60 路一小时测试中，解码输出携带的内部帧 ID 已经处于
`muxer`，却再次被移到更早的 `source-convert`。Savant 0.6.0 / savant_rs
1.13.0 的原生 C API 在此处触发 Rust panic，进程退出后由 Docker 重启。
Opus 的分析已核对，但 GitHub main 和 analysis-budget 分支均没有实现此保护。

本修改替换 `source-convert` 的原生阶段移动探针：

- 通过 Python `VideoPipeline.move_as_is` 接口移动帧；该接口将同一非法倒退
  返回为可捕获的 `ValueError`，原生 C API 则中止进程。
- 每个解码输出 pad 使用加锁的 1,024 条身份历史，阻止同一 ID 在原帧尚处于
  source-convert 时再次放行；不会用最大 ID 判断新旧，因此合法乱序 ID 可通过。
- 历史淘汰后仍执行安全阶段检查；不存在、已打包、来源不符、无有效元数据的
  缓冲区均拒绝。拒绝时只丢弃该缓冲区，不修改 UUID/PTS，不删除原在途帧。
- 按来源/原因计数，并保留初始及按二次幂间隔的诊断日志。
- 安装器在写入前检查全部补丁与新增 helper，支持已知旧覆盖版本；未知版本
  或缺失 helper 会阻止安装，避免半套补丁启动。

这是对进程崩溃的保护。它不能证明解码重复输出的上游原因已经修复，也不能
修复损坏的压缩视频。被拒绝的分析帧仍可能使事件漏检，必须在实测中统计。

## 已完成验证

- 13 项帧身份/并发/异常路径测试通过。
- 9 项安装器与校验和测试通过；已有部署接线测试通过，合计 23 项相关测试。
- 运行两组新增测试与整个部署合同测试文件：修改后 47 passed / 4 failed；未修改的精确基线
  为 25 passed / 同样 4 failed。失败项是缺少 CLAUDE.md、生成的 sources 配置、
  以及既有运行脚本清单不一致，未作为本补丁通过项。
- 在 uos157 实际使用的 Savant 镜像中，首次安装及重复安装通过。
- CPU 原生集成测试使用真实 Gst.Pad、Gst.Buffer、Savant 元数据和 Rust
  VideoPipeline：两条合法帧通过，四条重复/阶段倒退/无元数据输出被丢弃；
  进程存活，后续帧可继续通过，原始 UUID 保留。

可复现集成入口：`python scripts/tools/check_decoded_frame_guard.py`，在仓库挂载
到对应 Savant 镜像内运行。无需 GPU；裸 CPU 容器可设置空的 GST_PLUGIN_PATH
与 GST_PLUGIN_SYSTEM_PATH，避免扫描不需要的 CUDA 插件。
